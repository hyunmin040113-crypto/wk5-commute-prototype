# 출근길 프로토타입 — 이동시간을 내가 고른 활동으로

대중교통 통학·출퇴근자가 **이동시간을 원하는 활동에 쓰도록 돕는 앱**의 인터랙티브 프로토타입입니다.
PRD(26.10.05)와 사용자 시나리오(김나리, 30세 직장인) 중 **출근 시나리오(오전 8시, 전자책 이어읽기)** 만 구현했습니다.

- 배포 주소: https://wk5-commute-prototype.vercel.app/ 
- 검증하려는 핵심 경험: **선택 → 시작 → 중단 → 복귀(RETURN POINT) → 완료**
- 기준 기기: iPhone 15 / 16 Pro (393 × 852pt)

---

## 1. 사용한 툴

| 툴 | 용도 |
|---|---|
| **Claude Code** (Claude 데스크톱 앱, Opus 5.5) | PRD·시나리오 학습 → 프로토타입용 프롬프트 작성 → HTML 프로토타입 구현 → 내장 브라우저로 화면별 동작 검증 |
| **ChatGPT Codex** | 1차 시도 (실패, 아래 '실패한 시도' 참고) |
| **로우파이 레퍼런스 이미지 8장** | 화면 구성·문구·톤 기준 (홈 / 이동 중 / 승강장 / 활동 중 / 이동 구간 / 잠깐 알림 / RETURN POINT / 이동 기록) |
| **PRD 문서, 시나리오 문서** | 문제 정의, 제작 범위, 예외 상황, 화면 문구의 근거 |
| **GitHub + Vercel** | 저장소에 `index.html`을 올리면 Vercel이 자동 배포 |

**기술 구성:** HTML, CSS, 바닐라 JavaScript로 만든 **단일 파일(`index.html`)** 입니다.
빌드 과정이나 패키지 설치가 없고, 외부에서 불러오는 것은 Pretendard 웹폰트(CDN)뿐입니다.

## 2. 효과가 있었던 핵심 프롬프트

이번에는 바로 "만들어줘"라고 하지 않고, **맥락 학습 → 프롬프트 설계 → 제약 조건 추가 → 구현** 순서로 나눠서 진행했습니다.

### ① 맥락부터 먼저 학습시키기
> 우리의 프로젝트 prd, 시나리오 학습해.

- 구현 요청 전에 PRD와 시나리오를 먼저 읽게 하고, 요약과 함께 **문서 간 충돌 지점**을 짚게 했습니다.
- 이때 짚은 충돌: 퇴근 알림에서 활동 선택 단계가 생략되는 문제, 환승 직전 문구가 출근("여기까지 저장")과 퇴근("마무리할까요?")에서 서로 다른 문제, 앱 제한 기능이 PRD에는 있는데 시나리오에는 없는 문제.
- 효과: 이후 모든 결과물이 PRD의 **'이번에 뺄 것'**(자동 전환, 피로도 입력, 실시간 교통 연동, 게임화 등)을 지키며 만들어졌습니다.

### ② 범위를 좁히고, 레퍼런스의 역할을 정해주고, '프롬프트'를 먼저 쓰게 하기
> 시나리오에서 낮 부분만 프로토타입 만들고싶어. 첨부한 이미지는 로우파이 레퍼런스라고 생각해줘. 프롬프트 작성해줘.

- **범위 제한:** 출근·퇴근 중 **출근 하나만** 만들도록 했습니다.
- **레퍼런스 역할 지정:** 이미지는 픽셀 단위로 따라 그릴 시안이 아니라, 화면 구성과 톤의 기준이라고 알려줬습니다.
- **프롬프트 먼저:** 바로 코드를 짜게 하지 않고, 구현용 프롬프트([PROMPT_출근프로토타입.md](../PROMPT_출근프로토타입.md))를 먼저 쓰게 해서 검토할 수 있었습니다. 이 프롬프트에는 다음이 들어갔습니다.
  - 화면 9개와 분기 1개를 **화면별로 정의**: 헤더, 문구, 버튼, 다음 화면
  - 시나리오 구간과 화면을 1:1로 연결 (3.1 → S1 … 3.9 → S9)
  - **디자인 시스템 명시**: 컬러 토큰, 타이포, 카드, 버튼, 아이콘 규칙
  - **가상 데이터 표**: 페이지, 구간별 시간, 결과 수치
  - **UX 원칙 7개**와 **제외 범위**
  - 사용성 테스트용 **시뮬레이션 패널(TEST 탭)** 요구사항
- 프롬프트를 쓰는 과정에서 시나리오의 논리 오류도 드러났습니다. 첫 구간에서 18분을 읽었는데 복귀 지점이 여전히 132p로 되어 있던 부분을 **132p → 141p → 151p**로 고쳤습니다.

### ③ 출력 형태와 배포 환경을 처음부터 제약으로 주기
> 아이폰 사이즈 잘 체크해서 아이폰에 출시할 '앱' 비율로 만들어야하는거 잊지말고. 나중에 만든거 버셀에 임시로 배포도 할거니까 참고해서 프로토타입 만들어줘.

- **아이폰 비율:** 393×852pt 기준으로 만들고, 상단 상태바·다이내믹 아일랜드 영역(54pt)과 하단 홈 인디케이터 영역(34pt)을 반영했습니다.
  - PC에서는 아이폰 프레임 안에 표시되고, 창 크기에 맞춰 자동으로 줄어듭니다.
  - 실제 폰에서는 프레임 없이 전체 화면으로 표시되고, `safe-area-inset`으로 노치와 홈 바 영역을 피합니다.
- **배포 환경:** Vercel 배포를 미리 알려줘서 **빌드가 필요 없는 단일 HTML 파일**로 만들게 했습니다. 깨질 수 있는 지점(빌드 설정, 경로, 의존성)을 처음부터 없앤 셈입니다.
- 구현 뒤에는 Claude가 내장 브라우저에서 393×852로 화면을 하나씩 열고, 전체 흐름을 직접 실행해 콘솔 오류와 상태 값을 확인했습니다. 이 과정에서 TEST 패널로 앞 구간으로 되돌아가도 페이지 수가 초기화되지 않는 버그를 발견해 고쳤습니다.

## 3. 실패한 시도 — ChatGPT Codex

### 무엇이 같았나
Claude와 Codex 모두 **같은 PRD와 시나리오 문서**를 전달했습니다. 입력 자료는 같았는데 결과가 달랐습니다.

### 무엇이 달랐나 (실패 원인)

| | Codex 시도 (실패) | Claude 시도 (성공) |
|---|---|---|
| **프롬프트** | 구조 없이 짧게 요청 | 맥락 학습 → 프롬프트 설계 → 구현으로 단계를 나눔 |
| **범위** | 출근·퇴근을 모두 만들게 해서 **결과물이 너무 커짐** | **출근 하나만**으로 제한 |
| **화면 정의** | 화면 목록을 주지 않아 **레퍼런스에 없는 화면이 생기고**, 필요한 화면은 빠짐 | 화면 9개와 분기 1개를 문구·버튼·이동 대상까지 명시 |
| **디자인 시스템** | 따로 정해달라고 하지 않음 → 화면마다 스타일이 제각각 | 컬러 토큰, 타이포, 컴포넌트 규칙을 프롬프트에 명시 |
| **기기·배포 조건** | 사전 제약 없음 | 아이폰 비율과 Vercel 배포를 처음부터 제약으로 줌 |
| **결과** | **Vercel 배포 후 화면이 깨짐** | 배포용 단일 파일, 화면별 동작 검증 완료 |

**정리하면:** AI에게 "무엇을 만들지"만 주고 **"어디까지, 어떤 화면을, 어떤 규칙으로, 어떤 환경에서"** 는 주지 않았던 것이 실패의 핵심이었습니다.
범위가 넓고 화면과 규칙이 정해져 있지 않으면, AI가 빈칸을 스스로 채우면서 결과물이 커지고 일관성이 무너집니다.

### Vercel에서 깨진 이유 (추정)
당시 빌드 로그를 남기지 않아 정확한 원인은 확인하지 못했습니다. Codex 같은 도구는 보통 **Vite + React/TypeScript 프로젝트**를 만드는데, 그 구조에서 Vercel 배포가 깨지는 흔한 원인은 아래와 같습니다.

1. **빌드 설정 불일치**: Framework Preset, Output Directory(`dist`), Root Directory가 실제 프로젝트 구조와 맞지 않으면 빈 화면이나 404가 뜹니다.
2. **로컬에서는 되는데 배포 빌드에서만 실패**: 개발 서버(`vite dev`)는 타입 오류를 무시하지만, 배포 빌드(`tsc -b && vite build`)는 타입 오류가 있으면 실패합니다.
3. **파일명 대소문자 문제**: Windows는 `Header.tsx`와 `header.tsx`를 같은 파일로 보지만, Vercel 서버(Linux)는 다른 파일로 봅니다. 그래서 import 경로가 틀려 빌드가 실패합니다.
4. **경로(`base`) 설정**: `vite.config`의 `base`나 이미지·폰트를 `/src/...` 같은 절대경로로 쓰면 배포 후 리소스를 찾지 못해 스타일이나 이미지가 빠집니다.
5. **패키지 매니저 불일치**: `pnpm-lock.yaml`이 있는데 Vercel의 pnpm 버전이 다르거나, lock 파일과 `package.json`이 맞지 않으면 설치 단계에서 실패합니다.
6. **레이아웃 자체의 문제**: 기기 크기를 고려하지 않고 고정 픽셀로 짠 화면은 배포 후 실제 폰이나 다른 창 크기에서 열면 겹치거나 잘립니다.

**다음에 확인할 것:** Vercel의 **Deployments → 실패한 배포 → Build Logs**에서 빨간 에러 줄을 확인하면 위 중 어느 것인지 바로 알 수 있습니다.
이번 프로토타입은 이런 위험을 피하려고 **빌드가 없는 단일 HTML**로 만들었습니다.

## 4. 남은 한계

### 기능 범위
- **퇴근 시나리오(해리포터 이어보기)는 구현하지 않았습니다.** 홈 화면의 02(해리포터), 03(뉴스) 카드는 누르면 안내 메시지만 뜹니다.
- 하단 탭 중 **경로, 마이페이지는 동작하지 않습니다.** 기록 탭은 이동을 마친 뒤에만 열립니다. 일/주/월 통계 화면(PRD 7번)은 없습니다.
- **활동 등록 및 앱 연결 단계(PRD 1번)가 없습니다.** 활동 3개가 이미 등록된 상태로 시작합니다.
- **앱 제한 기능(PRD 6번)은 구현하지 않았습니다.** 이탈 시에는 부드러운 상기 알림만 뜹니다.
- **패턴 기반 제안**("보통 이 시간대에는 독서를 선택했어요")은 실제 기록이 아닌 고정 문구입니다.

### 데이터와 연동
- 모든 데이터는 **가상 데이터**입니다. 실시간 교통정보, 전자책 앱의 실제 진행 위치, SNS 사용 감지는 연동하지 않았습니다.
  - 열차 도착 시간과 환승 시점은 가상 시계(08:00 출발 기준)와 TEST 패널로 흉내 냈습니다.
  - '밀리의 서재' 화면은 연결 앱을 대신하는 더미 화면입니다. 앱 아이콘과 책 표지도 실제 로고·표지가 아니라 임의로 그린 그림입니다.
- 독서 속도는 **약 100초당 1페이지**로 정했습니다(32분에 약 19페이지). 실제 사용자 속도와 다릅니다.
- **저장 기능이 없어서** 새로고침하면 처음(132p)으로 돌아갑니다.

### 시나리오와 다르게 처리한 부분
- 복귀 지점 페이지를 원본 시나리오의 132p에서 **141p**로 바꿨습니다. 첫 구간에서 읽은 만큼 반영하기 위해서입니다.
- 원본 시나리오에서 SNS 이탈은 **퇴근** 장면(4.3)인데, 레퍼런스의 '잠깐 알림' 화면에 맞춰 **출근 흐름의 분기**로 넣었습니다.
- 환승 직전 안내(3.5)는 레퍼런스에 별도 화면이 없어서, 활동 중 화면 위에 뜨는 **작은 배너**로 만들었습니다.

### 검증 측면
- **실제 아이폰에서는 아직 테스트하지 않았습니다.** 데스크톱 브라우저의 393×852 화면 크기 흉내로만 확인했습니다. Safari의 safe-area 처리, 홈 화면 추가 시 동작은 실기기 확인이 필요합니다.
- PRD의 '남은 질문' 중 **개입 타이밍(9번)과 개입 강도(10번) 비교**는 아직 할 수 없습니다. 버전이 하나뿐이라 A/B 비교용 변형 화면이 없습니다.
- 접근성(스크린리더, 글자 크기 확대)과 다크 모드는 고려하지 않았습니다.
- 폰트를 외부 CDN에서 불러오기 때문에, 네트워크가 느리면 처음에 시스템 폰트로 잠깐 보일 수 있습니다.

## 사용 방법 (사용성 테스트 진행자용)

1. 배포 주소를 아이폰 Safari에서 엽니다. 공유 → '홈 화면에 추가'를 하면 주소창 없이 앱처럼 열립니다.
2. 홈에서 **전자책 이어읽기**를 눌러 시작합니다.
3. 화면 오른쪽 가장자리의 **TEST 탭**을 누르면 시뮬레이션 패널이 열립니다.
   - **구간 이동**: 도보 / 승강장 1 / 지하철 1구간 / 환승 / 승강장 2 / 지하철 2구간 / 하차
   - **상황 만들기**: 환승 2분 전 / SNS로 이탈 / 잠금화면 보기 / 하차 도착
   - **시간 배속**: 1x / 10x(기본) / 60x
   - **처음부터 다시**: 132p로 초기화

| 가상 시각 | 구간 |
|---|---|
| 08:00 | 출발 (역까지 도보 7분) |
| 08:07 | 승강장 1 대기 |
| 08:10 | 지하철 1구간 (132p → 141p) |
| 08:28 | 환승 도보 5분 |
| 08:33 | 승강장 2 대기 (RETURN POINT) |
| 08:36 | 지하철 2구간 (141p → 151p) |
| 08:51 | 하차, 기록 확인 (32분, 132p → 151p) |
